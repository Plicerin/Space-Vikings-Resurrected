# REA-generated disassembly

> Note (2026-11-12): `README_COMPLETE.md`, `JAVASCRIPT_REMAKE_PLAN.md`, `README-original-handover.md` and the `js-remake/` and `modern/web/src/` code were removed from the tree as superseded; they remain in the git history (before the cleanup commit). Where this file names them it is the record of a correction made at the time.


This directory holds decompiled output from [REA (Reverse Engineer Anything)](https://github.com/morluto/rea),
run against Ghidra 12.1.2 with a full JDK 27, for every real 6502 code binary
extracted from the Space Vikings disk. It supplements the hand-written
disassembly in `disassembly/` — that directory has raw instruction-by-instruction
listings from this project's own custom disassembler; this directory adds
automatic function-boundary detection, call graphs, and C-like decompiled
pseudocode on top, generated by Ghidra via REA's headerless raw-binary mode
(`--target-format raw-binary --architecture 6502 --entry-point 0x...`).

Each subdirectory is named `<binary name> (<load address>)` and contains:
- `decompile-index.json` — the function manifest REA produced (addresses, names, counts).
- `functions/<address>.c` — one decompiled pseudocode file per identified function,
  with REA's own provenance/limitations header comment preserved. This is Ghidra
  decompiler output, not original source, and not guaranteed text-equivalent to
  any other disassembler's output — treat it as a reading aid, not ground truth,
  and cross-check against the hand-written disassembly in `disassembly/` where it matters.

Load addresses are the verified `BLOAD` addresses from `START.bas` (see
`HANDOVER.md` and `CATALOG_FINDINGS.md`), not the (sometimes wrong) catalog
header addresses or the custom disassembler's default `$8000`/`$1000` fallback.

`CATALOG_FINDINGS.md` — not run through a code disassembler.

## EXPL is not code

`EXPL` was previously assumed to be a 34-byte sound routine (see the now-corrected
claims in `README_COMPLETE.md`, `GAME_MECHANICS_DOCUMENTATION.md`, and
`analysis/comprehensive_memory_layout.md`). REA's Ghidra decode rejects it as
invalid 6502 instruction data at both candidate load addresses (`$9100`, the
custom disassembler's default, and `$9270`, the catalog-documented address) —
decoding fails on the very first byte either way. Cross-checked against the
BASIC source: `H_D.bas` and `S_X.bas` only ever reference `EXPL` through
Applesoft's `DRAW` shape-table command, never `CALL`. It's shape-table graphics
data for the explosion animation, not executable code, and it does not call
`SOUND GEN`. No decompiled output exists for it here for that reason.

## Selected findings worth flagging for the port

- **`$03CD`/`$03CE` are probably not "crew morale"/"training level."** REA's
  decompile of `HI-RES CHARACTER GENERATOR` shows both bytes used as
  inverse/flash-mode text flags, consistent with `analysis/comprehensive_memory_layout.md`'s
  independent "likely screen/display control" guess and inconsistent with the
  "crew morale" label that made it into `GAME_MECHANICS_DOCUMENTATION.md`,
  `JAVASCRIPT_REMAKE_PLAN.md`, and from there into `js-remake/src/*` (several
  files hardcode `0x03CE` as a morale stat). The label is corrected in the
  docs above; the JS port's code still assumes "morale" and has not been
  updated to match — flagging for whoever picks this back up, since the port
  is non-functional stub code regardless (see `HANDOVER.md`/prior investigation
  notes on `js-remake`'s broken imports).
- **`LASER` does not call `SOUND GEN`.** It hits the speaker soft-switch `$C030`
  directly in its own nested countdown loops, despite the naming pattern
  suggesting it might delegate to the shared tone generator.
- **`$6000` (the start of `LO-HI A2-3D1`) is a thunk to `$611C`** — confirms
  `HANDOVER.md`'s own open question ("identify the routine table or jump table
  near the start") without needing manual Ghidra work.
- **`MEM TRANSFER A`'s block-copy mechanics are now exact**: a loop of 64
  calls to a 40-byte copy helper, driven by two parallel pointer tables at
  `$8BEC`/`$8D7C`, indexed by the shared counter at `$9532`.
- **`TRANLIT.OBJ0`'s entry point is a 4-way command dispatcher** keyed on a
  mode byte at `$9517`, not a single linear routine.

## Regenerating

```bash
export JAVA_HOME=/usr/lib/jvm/java-27-openjdk   # any full JDK 21+
rea decompile-all "extracted/<name>.payload.bin" \
  --target-format raw-binary --architecture 6502 \
  --entry-point 0x<address> --provider ghidra \
  --output "rea-disassembly/<name> (0x<address>)" --json
```

REA (`rea-agents` on npm) and a Ghidra install are both required; see the
main project investigation notes for setup details.
